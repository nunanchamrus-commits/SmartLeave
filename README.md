# 🌿 SmartLeave - ระบบบริหารจัดการวันเวลาของการลา
### สำนักงานสหกรณ์จังหวัดขอนแก่น (Khon Kaen Provincial Cooperative Office)

**SmartLeave** คือระบบบริหารจัดการวันเวลาของการลา สถิติวันลา และแบบฟอร์มราชการอิเล็กทรอนิกส์สำหรับบุคลากรภาครัฐ ออกแบบและพัฒนาขึ้นเพื่อรองรับโครงสร้างการทำงาน ระเบียบการลาทางราชการ และการตัดรอบปีงบประมาณของสำนักงานสหกรณ์จังหวัดขอนแก่นอย่างสมบูรณ์แบบ บนสถาปัตยกรรม **Serverless Full-Stack (React 18 + Vite + Tailwind CSS + Cloudflare Workers + Cloudflare D1 SQLite)** รองรับการใช้งานทั้งบนคอมพิวเตอร์ แท็บเล็ต และสมาร์ตโฟนทุกขนาดหน้าจอ

## 🌟 จุดเด่นและฟีเจอร์หลัก (Key Features)

### 1. ระบบยืนยันตัวตนและความปลอดภัย (Authentication & PDPA)
- **เข้าสู่ระบบด้วยชื่อ-สกุลภาษาอังกฤษ:** รองรับการเข้าสู่ระบบด้วยชื่อ-สกุลภาษาอังกฤษทางการตามบัตรประจำตัวเจ้าหน้าที่ (เช่น `Panika Thammoeang`, `Suda Jaidee`) หรืออีเมล พร้อมรหัสผ่านความปลอดภัยสูง (ความยาวขั้นต่ำ 8 ตัวอักษร)
- **การจำแนกสิทธิ์ตามบทบาท (Role-Based Access Control - RBAC):**
  - 👤 **โหมดผู้ใช้งานทั่วไป (User / Employee):** แดชบอร์ดสรุปยอดวันลาส่วนบุคคล, ยื่นคำขอลาออนไลน์, ติดตามสถานะคำขอลา, ยื่นขอยกเลิกวันลา, ปฏิทินวันลาของตนเอง, พิมพ์ใบลา PDF และแก้ไขข้อมูลส่วนตัว
  - 🛡️ **โหมดผู้ดูแลระบบและผู้อนุมัติ (Admin & Approver):** แดชบอร์ดสถิติภาพรวม, พอร์ทัลพิจารณาอนุมัติคำขอลา, พอร์ทัลพิจารณาคำขอยกเลิกวันลาพร้อมระบบคืนโควตาอัตโนมัติ, จัดการรายชื่อบุคลากรและปรับโควตาวันลา, หน้ารายงานสถิติการลาประจำปีงบประมาณ และปฏิทินกลางขององค์กร
- **ระบบคุ้มครองข้อมูลส่วนบุคคล (PDPA Consent):** ตรวจสอบและบันทึกประวัติการยินยอมตาม พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 ลงในตาราง `pdpa_consents` พร้อมเก็บบันทึกประวัติ `pdpa_audit_logs`
- **ระบบกู้คืนรหัสผ่านด้วย OTP ทางอีเมล:** รองรับการขอรับรหัส OTP 6 หลักผ่านอีเมลเพื่อยืนยันตัวตนก่อนตั้งรหัสผ่านใหม่

### 2. ระเบียบวันลาและการตัดรอบปีงบประมาณราชการ (Civil Service Leave Rules & Fiscal Year)

#### 📅 ระบบการตัดรอบตามปีงบประมาณ (Fiscal Year Cycle)
ระบบคิดคำนวณและตัดรอบวันลาตามปีงบประมาณราชการอย่างแม่นยำ (เช่น ปีงบประมาณ 2569 และปีงบประมาณถัดไป):
- **รอบที่ 1:** วันที่ 1 ตุลาคม 2568 – 31 มีนาคม 2569 (ช่วงประเมินผลการปฏิบัติงานรอบที่ 1)
- **รอบที่ 2:** วันที่ 1 เมษายน 2569 – 30 กันยายน 2569 (ช่วงประเมินผลการปฏิบัติงานรอบที่ 2)
- รองรับการกรองข้อมูล การส่งออก และการรายงานสถิติตามรอบปีงบประมาณและรอบประเมิน

#### ⏱️ เงื่อนไขการเลือกลาวันที่ย้อนหลัง (Backdated Leave Rules)
- **การลาพักผ่อน (Vacation Leave) & การลากิจส่วนตัว (Personal Leave):** **ไม่สามารถเลือกลาย้อนหลังได้** (ระบบล็อกให้เลือกได้ตั้งแต่วันปัจจุบันเป็นต้นไปเท่านั้น)
- **การลาป่วย (Sick Leave):** **สามารถเลือกลาย้อนหลังได้ไม่เกิน 7 วัน** (นับย้อนหลังจากวันปัจจุบัน)

#### 📊 สิทธิ์และโควตาวันลาตามระเบียบสำนักนายกรัฐมนตรี
| ประเภทบุคลากร (Employment Type) | ลาป่วย (Sick) | ลาคลอดบุตร (Maternity) | ลากิจส่วนตัว (Personal) | ลาพักผ่อน (Vacation) |
| :--- | :---: | :---: | :---: | :---: |
| **ข้าราชการ (Civil Servant)** | 60 วัน | 90 วัน | 45 วัน | 10 วัน (สะสมได้ตามระเบียบ) |
| **ลูกจ้างประจำ (Permanent Employee)** | 60 วัน | 90 วัน | 45 วัน | 10 วัน |
| **พนักงานราชการ (Government Employee)** | เท่าที่ป่วยจริง (เบิกได้ 30 วัน) | 90 วัน | 10 วัน | 10 วัน |

### 3. ระบบยื่นคำขอลาและการพิจารณาอนุมัติ (Leave Request & Approver Workflow)
- **ยื่นคำขอลาออนไลน์:** คำนวณวันลาคงเหลือแบบ Real-time รองรับทั้งแบบเต็มวัน, ครึ่งวันเช้า และครึ่งวันบ่าย พร้อมกล่องปฏิทินเลือกวันที่ พ.ศ. ภาษาไทย (`ThaiDatePicker`)
- **การระบุผู้ปฏิบัติหน้าที่แทน:** บันทึกและระบุชื่อผู้ปฏิบัติหน้าที่แทนระหว่างลา
- **พอร์ทัลผู้อนุมัติ (Approver Portal):** 
  - หัวหน้าฝ่าย/ผู้อำนวยการตรวจสอบรายละเอียดเหตุผลและช่วงเวลาการลา
  - ดำเนินการ **อนุมัติ**, **ไม่อนุมัติ**, **อยู่ระหว่างตรวจสอบ** หรือ **ยังไม่ยื่นเอกสาร** พร้อมระบุข้อคิดเห็น/หมายเหตุ
  - เมื่อได้รับการอนุมัติ ระบบจะตัดยอดวันลาคงเหลือในฐานข้อมูล D1 ทันที

---

### 4. ระบบขอยกเลิกวันลาและการคืนสิทธิ์วันลาอัตโนมัติ (Cancel Leave Request & Auto Quota Refund)
- พนักงานสามารถยื่นขอยกเลิกวันลาสำหรับคำขอที่เคยยื่นไปแล้ว (ยกเลิกทั้งช่วง หรือระบุเฉพาะบางวันที่ต้องการยกเลิก) พร้อมระบุเหตุผลและแนบเอกสาร
- ผู้ดูแลระบบ/ผู้อนุมัติสามารถตรวจสอบคำขอยกเลิกในหน้า **"พิจารณายกเลิกวันลา" (`AdminCancelApprovalsView`)**
- **ระบบคืนโควตาอัตโนมัติ (Auto Quota Refund):** เมื่อผู้ดูแลระบบกด "อนุญาต" ยกเลิกวันลา ระบบจะคำนวณและคืนจำนวนวันลากลับเข้าโควตาส่วนบุคคลของพนักงานโดยอัตโนมัติทันที
- รองรับการดาวน์โหลดและพิมพ์ **ใบขอยกเลิกวันลาอิเล็กทรอนิกส์ (PDF)** ตามแบบราชการ

---

### 5. การออกเอกสารแบบฟอร์มราชการ PDF (Official PDF Generation)
- **พิมพ์ใบลาอิเล็กทรอนิกส์ (PDF):** สร้างไฟล์ PDF แบบฟอร์มใบลาตามระเบียบราชการไทย สวยงาม ถูกต้องตามโครงสร้างแบบฟอร์มราชการ ทั้งใบลาพักผ่อน, ใบลาป่วย/ลากิจส่วนตัว และใบลาคลอดบุตร
- **พิมพ์ใบขอยกเลิกวันลา (PDF):** สร้างไฟล์ PDF แบบฟอร์มขอยกเลิกวันลาพร้อมระบุข้อมูลการอนุมัติเดิม วันที่ขอยกเลิก และลายมือชื่อ
- รองรับการเปิดพรีวิวและดาวน์โหลดเอกสารแนบ (รูปภาพหรือ PDF) ภายในระบบได้โดยตรง

---

### 6. หน้ารายงานสถิติการลาและแดชบอร์ด (Reports & Analytics)
- **การนับสถิติเฉพาะคำขอที่อนุมัติแล้ว:** ในหน้ารายงานสถิติการลา (`ReportsView`) กราฟสถิติประจำเดือน (Monthly Trend Bar Chart), กราฟสัดส่วนประเภทการลา (Type Breakdown), สถิติแยกตามกลุ่ม/ฝ่าย (Department Breakdown) และยอดวันลารวมทั้งหมด จะคำนวณและแสดงผล **เฉพาะคำขอที่ได้รับการอนุมัติแล้ว (`status === 'อนุมัติ'`) เท่านั้น** คำขอที่ยังรอการอนุมัติหรือยกเลิกจะไม่ถูกนำมานับรวม
- **แดชบอร์ดผู้บริหาร (Admin Dashboard):** แสดงภาพรวมคำขอรอพิจารณา, บุคลากรที่ลาในวันนี้, สถิติประจำวัน และแจ้งเตือนสำคัญ

---

### 7. รองรับการใช้งานบนโทรศัพท์มือถือเต็มรูปแบบ (100% Mobile Responsive)
- **แถบนำทางด้านล่างสำหรับมือถือ (Mobile Bottom Navigation):** แถบเมนูด้านล่างหน้าจอสไตล์แอปพลิเคชันมือถือ พร้อมปุ่ม "+ ขอลา" เด่นตรงกลางที่แตะเปิดฟอร์มขอลาได้ทันทีจากทุกหน้า
- **Responsive Cards แทนตารางกว้าง:** แปลงตาราง 9 คอลัมน์ในหน้าจัดการพนักงาน และตารางประวัติการลา เป็น **Touch Cards** แสดงข้อมูลครบถ้วน อ่านง่าย สัมผัสสะดวก ไม่ต้องเลื่อนจอซ้ายขวา
- **Slide-out Drawer Navigation:** เมนูข้างแบบสไลด์พร้อมปุ่มปิด (X) บนหน้าจอมือถือ
- **Touch-Friendly Modals:** หน้าต่าง Popup ทุกบานปรับขนาดและ Padding ให้รองรับขอบเขตหน้าจอมือถือ (`max-h-[92dvh]`, `h-[100dvh]`) ป้องกันปัญหากล่องล้นจอหรือแถบเบราว์เซอร์บัง

## 💻 เทคโนโลยีที่ใช้พัฒนา (Tech Stack)

### Frontend
- **Core Framework:** [React 18.3](https://react.dev/) + [Vite 6.1](https://vitejs.dev/) (Single Page Application)
- **Styling:** [Tailwind CSS 3.4](https://tailwindcss.com/) + PostCSS + Autoprefixer
- **UI & Icons:** [Lucide React](https://lucide.dev/) (Modern Vector Icons)
- **Visual Feedback:** [Canvas Confetti](https://www.npmjs.com/package/canvas-confetti)
- **PDF Generation:** [pdf-lib](https://pdf-lib.js.org/) + [@pdf-lib/fontkit](https://www.npmjs.com/package/@pdf-lib/fontkit) + [html2pdf.js](https://www.npmjs.com/package/html2pdf.js)

### Backend & Cloud Infrastructure
- **Serverless API:** [Cloudflare Workers](https://workers.cloudflare.com/) (Edge Serverless Environment)
- **Database:** [Cloudflare D1](https://developers.cloudflare.com/d1/) (Distributed Serverless SQLite)
- **API Architecture:** RESTful JSON API with Bearer Token & Role-based Access Control
- **Schema Management:** Idempotent Auto-Migration on Worker Startup

## 🗄️ โครงสร้างฐานข้อมูล (Cloudflare D1 SQLite Schema)

ระบบใช้งาน Cloudflare D1 เป็นฐานข้อมูลแบบกระจายศูนย์ (Distributed Serverless SQLite) ประกอบด้วยตารางหลัก:
1. `users` — จัดเก็บข้อมูลบุคลากร ชื่อ-สกุล (ไทย-อังกฤษ), เพศ, ตำแหน่ง, สังกัดฝ่าย, ประเภทบุคลากร, สิทธิ์ (Role), โควตาวันลา และรหัสผ่านที่เข้ารหัส
2. `leave_requests` — จัดเก็บประวัติคำขอลา ประเภทการลา, วันที่เริ่ม-สิ้นสุด, จำนวนวัน, เหตุผล, ผู้ปฏิบัติหน้าที่แทน, สถานะการลา, ข้อมูลการขอยกเลิกวันลา และเอกสารแนบ
3. `announcements` — จัดเก็บรายการประกาศ ข่าวสารประชาสัมพันธ์ และวันหยุดราชการ
4. `audit_logs` — จัดเก็บบันทึกประวัติการกระทำสำคัญในระบบ (Audit Trail)
5. `pdpa_consents` — จัดเก็บบันทึกความยินยอมตาม พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคลรายบุคคล

## 🚀 วิธีการติดตั้งและรันระบบ (Getting Started)

### ข้อกำหนดเบื้องต้น (Prerequisites)
- [Node.js](https://nodejs.org/) (เวอร์ชัน 18 ขึ้นไป แนะนำ LTS)
- [npm](https://www.npmjs.com/) (มาพร้อมกับ Node.js) หรือ pnpm

### 1. ติดตั้ง Dependencies
```bash
npm install
```

### 2. รันระบบในสภาพแวดล้อม Development (Frontend)
```bash
npm run dev
```
เข้าใช้งานผ่านเบราว์เซอร์ที่: `http://localhost:5173`

### 3. รันหรือทดสอบ Backend API (Cloudflare Workers Local Dev)
```bash
npx wrangler dev
```

### 4. ตรวจสอบการ Build สำหรับ Production
```bash
npm run build
```
ไฟล์ที่คอมไพล์แล้วจะจัดเก็บในโฟลเดอร์ `dist/` พร้อมสำหรับการนำขึ้น Deploy (เช่น Cloudflare Pages หรือ Cloudflare Workers Assets)
